## 재개할 근거와 호출 범위

[기존 부분 실측](../content-safety-context-v2-evaluation-2026-10-30/README.md)은 29번째 HTTP 500에서 중단됐다.
정상 28회(후보별 14개)는 보존하고, 실패한 Luna 1회와 미실행 27회만 선택한다.
정책·표본·모델·요청 설정은 기존 `ko-context-proposal-v2`/Luna/Terra 계획과 같다.

| 항목 | 새 계획 |
| --- | --- |
| 전송할 고유 합성 문장 | 기존 28개 중 남은 14개 |
| 후보와 추가 호출 | `gpt-6-luna` 14 + `gpt-6.1-terra` 14 = 최대 28회 |
| 이전 실패 요청 재호출 | `expand-benign-03`/Luna 1회 |
| 이전에 시도하지 않은 요청 | 27회 |
| 완료 요청 재호출 | 0회 |
| 새 실행 중 자동 재시도 | 0회, 첫 실행 오류에서 전체 중단 |
| 누적 최대 요청 | 이전 29 + 추가 28 = 57회 |
| 새 요청의 초안/미정 | 초안 20회(후보별 10), 정답 미정 8회(후보별 4) |
| 이미지·음성·실제 사용자 자료 | 전송 0건 |

첫 순서는 실패했던 `expand-benign-03`/Luna이고 그 뒤 같은 문장의 Terra와 원래 순서의 나머지 요청이다.
[resume-plan.json](resume-plan.json)에 모델·ID·입력 해시·상태와 제한을 저장했다.
[transmission-preview.json](transmission-preview.json)에 실제 전송할 14개 합성 문장의 후보별 28회 목록과
정책 지시문·요청 schema/설정을 보존했다. 목록용 ID·후보명·상태는 로컬 표시이며 API user 입력은 `{text}`뿐이다.
제안 정답·그룹·해설·이전 관측 응답은 API에 보내지 않는다.

## 원본 검증과 실행 흐름

이번 도구는 다음 한 건의 커밋된 부분 보고서만 신뢰 기준으로 지원한다.

- 원본: [openai.json](../content-safety-context-v2-evaluation-2026-10-30/openai.json).
- 원본 JSON 정규화 지문: `f66d09d26fa3e3c30a8701d34ee2ced69dc8f8e113bc7d4a1b75f6effe1a6894`.
- 원래 호출 계획: `e1d605fa44cca0845fb5fc9aa749736a903ea816d4c99986847c007d37d65ef4`.
- 새 재개 계획: `63c0dce29e634c7b269328d64579133246b06c18f88175a6d438a2027874847d`.

`createContextResumeSession`은 원본을 한 번 직렬화해 지문을 검사하고 바로 그 스냅샷만 사용한다.
관측·라벨·수량·HTTP 상태·모델·시각 등 원본 내용이 바뀌면 재개를 거부한다.
현재 자료로 다시 만든 원래 계획도 비교하므로 정책·자료·요청 설정이 바뀌면 진행하지 않는다.
파일의 JSON 공백/줄바꿈 차이는 파싱으로 제거하지만 객체 키 순서 등 직렬화 결과 변경은 지문 불일치가 된다.
이 지문은 커밋한 기준자료와의 일치를 검사하며 공급자 응답의 외부 진위나 사람 검토를 증명하지 않는다.

세션과 요청 목록을 재귀적으로 동결하고 생성한 세션만 계획/실행 함수에 전달한다.
원래 호출 순서에서 정상 완료된 `(문장 ID, 후보)` 쌍만 제외한다. 실패는 성공으로 바꾸지 않고 새 관측을 요구한다.
부분집합 실행기는 빈 목록·중복·역순·미지 ID/후보·강제 문자열 변환을 거부한다.
공통 v2 어댑터와 실패 처리 실행기를 사용하며 기본 전체 56회 동작과 v1 계획 지문은 보존했다.

호출 흐름은 `고정 원본 검증 → 현재 정책/자료 일치 확인 → 남은 요청 동결 → 새 지문 확인 →
키 존재 확인 → 최대 28회 budget → 실제 어댑터 → 응답 검증 → 추가 관측과 누적 범위 분리`다.
다른 원본 경로·후보 선택을 받지 않으며 재개 중 또 실패해도 새 결과를 자동으로 연쇄 재개하지 않는다.

## 비용과 전송 조건

2026-10-30 확인한 [Luna 공식 단가](https://developers.openai.com/api/docs/models/gpt-6-luna)와
[Terra 공식 단가](https://developers.openai.com/api/docs/models/gpt-6.1-terra)를 유지한다.
백만 토큰당 입력/출력은 각각 $0.10/$0.50, $1/$5다. 입력에는 cache write 여유 단가 $0.125/$1.25를 적용했다.

| --- | --- | --- | --- |
| 회당 입력 2,000·출력 512토큰 | $0.007084 | $0.070840 | $0.077924 |
| 보수적 입력 10,000·출력 512토큰 | $0.021084 | $0.210840 | $0.231924 |

실제 청구액·계정 잔여량·계약·세금은 미확인이며 위 값은 확정 청구 상한이 아니다.
기존 실패 요청의 비용도 알 수 없으며 새 견적에 이미 발생한 비용을 포함하지 않았다.

Responses, reasoning none, default tier, store false, stream false, tools 없음 설정이다.
호출당 최대 20초, 출력 512토큰, text 1,200 UTF-8 bytes, 요청 body 8,192 bytes이며
현재 최대 직렬화 본문은 3,098 bytes다. 실제 입력·출력 usage 한도는 10,000/512로 유지한다.
외부에는 합성 텍스트·일반 정책·schema만 보내고 보관 조건은
[기존 v2 계획](../content-safety-context-v2-readiness-2026-10-30/README.md#외부-전송보관과-실행)을 따른다.
store false를 모든 외부 보관이 없다는 뜻으로 해석하지 않는다. 계정별 보관/지역 설정은 조회하지 않았다.

기존 56회 승인은 새 재개 실행의 승인이 아니다. 이전 실패 1회 재호출과 누적 57회를 포함한
새 계획을 확인받은 뒤에만 실제로 실행한다. 준비 이후 사용자가 안내된 추가 28회/비용에 대해 계속 진행을 승인해 1회 실행했다.

## 결과를 합치는 방식과 한계

새 출력의 `additionalEvaluation`은 새로 시도한 행만 포함한다. 원래 파일을 덮어쓰지 않는다.
`combined`에는 정상 완료된 관측만 원래 순서로 합치고 각 행의 `source=prior|resume`를 남긴다.
원래 HTTP 500 실패는 별도 원본과 `priorFailedAttempts=1`로 보존한다.
같은 문장의 새 성공 관측이 생기더라도 과거 실패 요청 수·비용 불확실성을 지우지 않는다.

추가 실행도 실패하면 새 failed 행은 additionalEvaluation에 남고 통합 범위는 미완료다.
원래 정상 완료 28개만으로 56개를 모두 완료했다고 표시하지 않는다.
정답 미정 4개는 expected null이며 모델의 allow/block/unavailable을 그대로 보존한다.
실제 unavailable 응답과 통신/형식 실패도 분리한다. 기대 라벨로 모델 답을 대체하지 않는다.

전부 정상 완료하더라도 통합 관측은 서로 다른 시각의 두 실행이다.
alias의 날짜 snapshot이 없어 같은 내부 모델 버전이었다고 보증하지 못하고 지연도 한 실행처럼 합산하지 않는다.
초안 24개와 미정 4개의 정책 검토 자료이며 독립 표본 검증·사람 라벨 검토·원본 미디어 품질을 대체하지 않는다.
`ready=false`, `productionPublicationAuthorized=false`, `independentlyValidated=false`, 사람 라벨/청취 미완료 flag를 유지한다.
