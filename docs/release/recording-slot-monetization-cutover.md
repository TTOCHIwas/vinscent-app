# 녹음 보관 슬롯 유료 전환 요구사항

## 1. 상태와 적용 시점

- 상태: 구현 보류
- 적용 시점: 정식 출시 직전
- 진행 방식: 구현, 로컬·스토어 결제 테스트, 운영 반영 순으로 진행한다.
- 현재 개발 작업에는 결제 연동이나 슬롯 정책 변경을 포함하지 않는다.

이 문서는 베타에서 사용하던 무료 녹음 보관 슬롯을 정식 출시 시 유료 슬롯으로
전환하기 위한 요구사항만 정의한다.

## 2. 확정 정책

- 슬롯은 개인이 아니라 현재 연결된 커플의 공용 녹음 보관 공간이다.
- 베타 기간에는 연결된 커플이 `+` 버튼으로 무료 슬롯을 최대 1개 열 수 있다.
- 베타 기간에 실제로 연 슬롯은 정식 출시 후에도 그대로 유지한다.
- 정식 출시 후에는 `+` 버튼을 누르면 결제 화면을 연다.
- 결제가 취소되거나 실패하면 슬롯 수는 바뀌지 않는다.
- 결제가 서버에서 검증된 경우에만 슬롯을 1개 추가한다.
- 이미 열린 슬롯과 저장된 녹음은 유료 전환 과정에서 삭제하거나 잠그지 않는다.
- 전체 슬롯 상한은 현재와 동일하게 10개로 유지한다.

별도의 베타 테스터 권한이나 복잡한 보상 원장을 만들지 않는다. 베타 때 열린
슬롯 수가 이미 `couple_recording_slot_settings.slot_limit`에 저장되므로 이 값을
그대로 유지해 베타 혜택을 보존한다.

## 3. 베타 커플의 범위

기본 정책은 **베타 기간에 직접 `+`를 눌러 슬롯을 연 커플만 무료 슬롯을
보유하는 것**이다. 베타 당시 연결되어 있었지만 슬롯을 열지 않은 커플에게
출시 후 자동으로 슬롯을 지급하지 않는다.

출시 전에 정책이 "베타 당시 연결된 모든 커플에게 1개 보장"으로 바뀌면,
출시 기준 시각에 해당하는 활성 커플의 `slot_limit`을 최소 1로 만드는 일회성
운영 DB 처리를 추가한다. 이 경우에도 별도 상시 권한 시스템은 만들지 않는다.

## 4. 현재 구현과 변경 지점

현재 `public.open_next_couple_recording_slot()`은 인증된 커플 사용자가 결제 없이
호출할 수 있고, `slot_limit`이 10이 될 때까지 1개씩 증가시킨다. 모바일의 녹음
보관함도 `슬롯 추가` 버튼에서 이 RPC를 직접 호출한다.

관련 코드:

- `supabase/migrations/20260629004000_fix_open_next_couple_recording_slot_ambiguity.sql`
- `apps/mobile/lib/features/recordings/data/supabase_couple_recording_slot_writer.dart`
- `apps/mobile/lib/features/recordings/presentation/recording_library_screen.dart`

정식 출시 전 다음과 같이 변경한다.

1. 베타 무료 추가 경로는 슬롯 1개까지만 허용한다.
2. 정식 출시 앱의 `+` 버튼은 슬롯 RPC 대신 스토어 결제 흐름을 시작한다.
3. 구매 영수증 또는 구매 토큰은 서버에서 검증한다.
4. 검증 성공 후 서버 전용 경로가 `slot_limit`을 원자적으로 1 증가시킨다.
5. 같은 거래가 재전송되어도 슬롯이 두 번 증가하지 않도록 거래 식별자를
   중복 처리한다.
6. 기존 클라이언트가 무료 RPC를 직접 호출해 결제를 우회하지 못하도록 공개
   실행 권한을 제거하거나 서버 검증이 필수인 함수로 교체한다.
7. 슬롯이 10개이면 구매 진입을 막고 기존 최대 한도 안내를 사용한다.

클라이언트에서 결제 화면만 추가하고 현재 공개 RPC를 유지하는 방식은 허용하지
않는다. 수정된 앱이나 이전 베타 앱에서 RPC를 직접 호출하면 결제를 우회할 수
있기 때문이다.

## 5. 출시 전 데이터 확인

운영 반영 전에 다음 값을 확인한다.

- 활성 커플별 현재 `slot_limit`
- `slot_limit`이 1보다 큰 베타 커플
- 열린 슬롯별 저장된 녹음 존재 여부
- 슬롯 상한 10개에 도달한 커플

베타 중 이미 2개 이상 열린 슬롯이 발견되더라도 기존 슬롯이나 녹음을 자동으로
삭제하지 않는다. 해당 데이터는 기존 이용 내역으로 보존하고, 출시 후 추가
슬롯부터 결제를 요구한다.

## 6. 전환 순서

1. 운영 DB에서 베타 슬롯 현황을 조회하고 결과를 보관한다.
2. Google Play와 App Store에 슬롯 상품과 테스트 계정을 준비한다.
3. 서버 구매 검증과 중복 거래 방지 경로를 먼저 배포한다.
4. 정식 출시 앱에서 `+` 버튼을 결제 흐름에 연결한다.
5. 공개 무료 슬롯 증가 경로를 차단한다.
6. 이전 베타 앱과 정식 출시 앱을 함께 사용해 우회 가능성을 확인한다.
7. 결제 테스트를 모두 통과한 빌드만 정식 출시한다.
8. 인앱 구입이 없다고 적힌 스토어 문구와 심사 안내를 실제 출시 기능에 맞게
   갱신한다.

## 7. 필수 테스트

- 베타에서 연 슬롯 1개가 앱 업데이트 후에도 표시된다.
- 베타에서 저장한 녹음이 업데이트 후에도 재생된다.
- 베타 무료 경로로 두 번째 슬롯을 열 수 없다.
- 신규 사용자가 `+`를 누르면 결제 화면이 열린다.
- 결제 취소와 실패 후 `slot_limit`이 변하지 않는다.
- 검증된 결제 1건당 슬롯이 정확히 1개 증가한다.
- 동일 거래를 여러 번 전달해도 슬롯은 한 번만 증가한다.
- 로그아웃, 재로그인, 앱 재설치 후 구매한 슬롯이 유지된다.
- 두 커플 구성원에게 증가한 슬롯 수가 동일하게 보인다.
- 구버전 베타 앱에서 무료 슬롯 증가 RPC를 직접 호출할 수 없다.
- 슬롯이 10개이면 추가 결제를 시작할 수 없다.
- Android와 iOS에서 각각 테스트 구매를 완료한다.

## 8. 이번 전환에서 제외

- AI 기능 해금 시 무료 슬롯 지급
- AI 해금 이후 1년 단위 슬롯 보상
- 질문 완료 개수에 따른 슬롯 보상
- 구독 상품
- 기존 슬롯 또는 녹음의 소유권 이전

위 항목은 추후 실제 도입 시 별도 요구사항으로 다룬다. 이번 작업은
`베타 무료 1개 유지 -> 정식 출시 후 추가 슬롯 결제` 전환에만 집중한다.
