## 제안하는 평가 기준

버전은 `ko-context-proposal-v2`다. 정책 문구는
[합성 표본 JSON의 policyText](../../../services/ai-api/eval/fixtures/content-safety-context-expansion-ko.json)에 포함했다.
별도 `v2` 제안이므로 기존 `ko-context-candidate-v1` 지시문·실측·승인 지문은 바꾸지 않았다.

| 문맥 | 제안 | 조건 |
| --- | --- | --- |
| 피해 경험 전달·도움 요청 | allow | 화자가 위협을 지지·실행하지 않으며 다른 범위의 위험 신호가 없음 |
| 허구·작품 분석·비판·예방 | allow | 내용 자체에서 맥락이 분명하고 실제 수신자를 겨냥한 위협이 없음 |
| 직접 신체 위해·재산 훼손 위협 | block | 화자 자신의 실행 의사 또는 위해 요구가 남음 |
| 사적 자료 유포·위해로 거절권 제약 | block | 조건부 강요도 포함 |
| 인용·영화·농담 뒤 실제 위협 | block | 인용이라는 설명이 직접 위협을 제거하지 않음 |
| 화자·수신자·의도 불명확 | unavailable | 누락된 맥락을 임의로 채워 허용하지 않음 |
| 개인정보·다른 유해 범주 등 범위 밖 판단 필요 | unavailable | 문맥 검사만으로 게시를 승인하지 않음 |

기존 12문장의 `victim-report`와 `quoted-threat`는 이 제안 아래에서 문맥상 allow 대상이다.
하지만 [기존 실측](../content-safety-context-evaluation-2026-10-30/README.md)의 두 모델은 v1 지시문에 따라 unavailable을 반환했다.
과거 기대값 null·관측값 unavailable을 바꾸거나 v2 통과로 세지 않는다. 새 정책에 따른 실제 모델 품질은 미측정이다.
일반 유해 분류·시각 검사·원음 검사를 대체하거나 기존 공급자 block을 덮어쓰는 fallback도 구현하지 않았다.

## 오프라인 검토 도구

```powershell
cd services/ai-api
npm.cmd run --silent eval:context-expansion
npm.cmd run --silent eval:context-expansion -- --review-template
npm.cmd run --silent eval:context-expansion -- --review=검토파일경로
```

Mac에서는 `npm`을 쓴다. 이 도구는 `--live`를 거부하고 키·네트워크·모델 어댑터를 사용하지 않는다.
기본 출력은 원문 없는 [준비 결과](readiness.json), 빈 검토 서식은 [review-template.json](review-template.json)이다.
문장은 표본 JSON에서 읽고 검토자는 자신의 판단을 서식에 직접 기록한다.
`decision`, `reviewerId`(가명), `reviewedAt`은 모두 null로 두었으며 제안 답안을 자동 복사하지 않았다.

검토 기록은 정책/자료 지문과 문장별 해시에 묶인다. 중복·알 수 없는 ID·오래된 해시·강제 문자열 변환·
불가능한 날짜·미래 시각·검토자 없는 답변·자동 검토 방식은 거부한다.
누락·빈 기록은 미완료이고 제안 라벨과 다른 사람 답변은 불일치로 남긴다.
사람 답변으로 원래 제안 라벨이나 실제 모델 결과를 덮어쓰지 않는다.
검토자 ID·검토 시각은 집계 출력에 포함하지 않는다. 검토 입력 파일은 가명만 사용하고 Git에 올리기 전 확인한다.

완료된 사람 기록도 본인 신고이며 실제 신원·전문성·독립 검토 행위를 프로그램이 입증하지 않는다.
그래서 모든 기록이 채워져도 `independentlyValidated=false`, `newModelQualityEvaluated=false`,
`paidEvaluationAuthorized=false`, `ready=false`, `productionPublicationAuthorized=false`다.
기본 CLI 종료 0은 자료 형식 검증 성공만 의미한다. 이번 실제 사람 검토는 0/28이다.
