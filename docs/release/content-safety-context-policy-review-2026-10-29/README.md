# 강요·금지 맥락 기준과 자동 검토

작성일: 2026-10-29. 사용자가 사람 청취는 미완료로 두고 자동 검토부터 진행하도록 지정했다.
실제 청취 기록은 생성하지 않았고 기존 8개 `humanReviewed=false`도 유지했다.
이번 새 외부 요청은 0건이다. 키 파일을 읽지 않았고 제품 저장·운영 DB/Storage·배포는 변경하지 않았다.

## 근거와 검토 결론

검토 근거는 기존 `content-safety-ko.ts`의 `coercion-01`·`boundary-03`,
미디어 manifest의 `image/audio-coercion-ko`·`image/audio-negation-ko`와
[34회 실측 보고서](../content-safety-media-evaluation-2026-10-29/README.md)다.
보고서에서는 네 사례 모두 추출 CER 0, 텍스트 moderation 판정에서 기대와 차이를 확인했다.
기존 허용/차단 라벨을 결과에 맞춰 바꾸지 않았다.

| 문맥 | 기존 기준 또는 새 초안 | 판단 근거 |
| --- | --- | --- |
| 거절을 사적 사진 유포 협박으로 제약 | 기존 차단 기준 유지 | 요구·조건과 유포 위해의 연결을 읽어야 한다. ‘사진’이나 ‘거절’ 단어만으로 판단하지 않는다. |
| 폭력·협박을 금지하는 의사 표현 | 기존 허용 기준 유지 | 위해 실행 의사와 위해 금지의 뜻을 구분한다. |
| 금지 문구와 직접 위협/유포 협박이 함께 있음 | 새 합성 대조문, 차단 초안 | ‘안 돼’가 있어도 다른 절의 실행 의사를 지우지 않는다. |
| 배고픔의 과장 관용구 / 상대 위해 실행 | 기존 허용/차단 기준 유지 | 같은 위험 단어의 유무보다 실제 대상과 의도를 읽어야 한다. |
| 일시적인 거리 두기 / 거리 두기를 막는 위해 협박 | 기존 허용 기준 + 차단 대조문 초안 | 자기 의사 표현과 상대 선택을 강제로 막는 행위를 구분한다. |
| 피해 진술·도움 요청 / 허구·인용 | 기존 자료에서 미정 | 임의로 허용/차단을 확정하지 않고 제품 정책 검토 대상으로 남긴다. |

새 대조문은 [content-safety-context-ko.ts](../../../services/ai-api/eval/fixtures/content-safety-context-ko.ts)에 있다.
12개 모두 `reviewStatus=draft`이고 기존 미디어 대본 5개와 추가 합성 문장 7개다.
6개 묶음에서 단순 위험 단어 차단과 부정어 기반 자동 허용의 한계를 검토한다.
2개 미정 문맥의 `expected=unavailable`은 정책 미결 표시다. ASR 실패의 증거나 최종 제품 차단 기준이 아니다.
향후 모델 평가에서는 결정된 초안 10개와 미정 2개를 구분하고, 미정 사례를 품질 통과 근거로 합산하지 않는다.
이번에는 이 12개에 모델을 호출하지 않아 실제 분류 성능·지연·비용이 측정되지 않았다.

## 실행 가능한 검토 도구

```powershell
cd services/ai-api
npm.cmd run --silent eval:policy-review
npm.cmd run --silent eval:policy-review -- --speech-template
# 실제 사람이 청취한 기록 파일을 별도로 작성한 경우에만 사용한다.
npm.cmd run --silent eval:policy-review -- --speech-review=경로/청취기록.json
```

Mac에서는 `npm`을 사용한다. 도구는 Node 표준 라이브러리만 사용하며 Windows OCR/Python·키가 필요 없다.
`--live`와 알 수 없는 인자는 거부한다. env 파일을 읽거나 API 어댑터를 호출하지 않는다.
이번에 저장한 [policy-review.json](policy-review.json)은 기존 실측 JSON을 재집계한 결과다.

| 재검토 항목 | 결과 |
| --- | --- |
| 기존 안전 판정 대상 | 18사례, 기대 일치 14 |
| 기존 오허용 / 오차단 | 2 / 2 |
| 불일치 대본 수 | 공백·NFC 정규화 후 2개. 같은 대본의 이미지/음성을 독립적인 네 문장 오류로 보지 않음 |
| 대조군의 잘못된 허용 | 0 |
| 사람 청취 | 완료 0, 대기 8 |
| 판정 상태 | 자동 분류 품질 미통과, 정책 초안, 게시 권한 없음 |
| 새 문맥 평가 | 12개 준비, 실제 모델 평가 미실행 |

이 명령은 현재 상태에서 JSON을 출력하고 종료 코드 1을 반환한다.
도구 고장이나 테스트 실패가 아니라 기존 품질 불일치·정책 초안·청취 대기를 드러내는 결과다.
단위 테스트가 통과했다고 분류 성능이 개선됐다는 뜻이 아니다.
이 도구는 검토 기록의 형식·자료 일관성을 확인하며 보고서의 진위나 사람의 신원을 증명하지 않는다.
모든 라벨·청취 결과가 일치하더라도 `ready=false`, `productionPublicationAuthorized=false`다.

## 증거와 실패 경계

- manifest와 실측의 해시, 각 사례 ID·입력 파일 해시·초안 기대 라벨·완료 수를 대조한다.
  누락·중복·라벨 덮어쓰기·오래된 해시·NaN 지표·잘못된 자료형은 검토 증거로 인정하지 않는다.
- HTTP 200과 기대 판정 일치를 분리한다. 실패한 HTTP와 대조군의 자동 허용도 별도 표시한다.
- 검토 시에만 LF/CRLF 체크아웃 차이를 허용한다. 기존 유료 호출 계획의 fingerprint 검증은 변경하지 않았다.
- 결과에는 사례 ID·해시·집계·대기 상태만 남긴다. 실제 들린 문장·검토자 ID·키는 출력하지 않는다.

[speech-review.template.json](speech-review.template.json)은 8개의 M4A/WAV 해시가 묶인 미완료 서식이다.
`heardText`, `reviewerId`, `reviewedAt`은 null이고 두 청취 여부도 false다.
대본을 관측 문장 칸에 자동으로 복사하지 않는다. 자동 ASR 결과나 보고서의
`humanListeningPerformed=true`만으로 사람 청취를 완료 처리하지 않는다.

나중에 실제 사람이 두 형식을 듣고 실제 들린 문장을 작성한 경우에만 두 청취 여부,
가명 검토자 ID, 실제 UTC ISO 시각을 기록한다. 사람 입력 문장과 대본을 NFC·공백·기호 정규화로 비교한다.
파일 해시 불일치·중복·알 수 없는 ID·자동 ASR을 청취로 표시한 기록·존재하지 않는 날짜·미래 시각은 거부한다.
필수 기록이 비었거나 한 형식만 들은 항목은 미완료다. 들린 말이 대본과 다르면 불일치로 남긴다.
이 서식은 청취자의 본인 신고 기록이며 실제 청취 행위를 프로그램으로 입증하지는 않는다.
현재는 사용자의 지시에 따라 서식을 채우지 않고 8개 모두 대기로 보존했다.

## 검증과 커밋

- baseline 413개 → 신규 30개 포함 전체 Node 회귀 443개 통과, 실패/건너뜀 0.
- 최초 RED `986f978b`, 판정 형식·날짜 RED `0ba62f25`, 해시 형식 RED `e32dfd75`.
- GREEN 구현 `b7381b3b`. 테스트와 구현을 분리했다. 기존 src의 공급자·게시 유스케이스는 수정하지 않았다.
- 검토 모듈 line/branch coverage 100%/93.38%, CLI 100%/60%.
  전체 로드 파일(테스트 포함)은 94.03%/86.87%다. 이는 라이브 분류 품질 수치가 아니다.
- TypeScript 독립 리뷰의 강제 문자열 변환 수용 문제를 회귀 테스트로 재현하고 보완한 뒤 재검토를 통과했다.

## 다음 평가와 구현 경계

정책 초안은 ‘어떤 문맥을 허용/차단해야 하는가’를 정의하고 공급자 판정은 그 초안을 얼마나 지키는지 측정한다.
기존 moderation 응답을 제품 정책과 같다고 보거나, 특정 문장 ID/단어/기대 라벨로 실제 모델 결과를 대체하지 않는다.
문맥 분류 후보를 붙일 때는 실제 OCR/ASR 텍스트를 입력으로 쓰고 출력 계약·실패/모호 상태와 정책 버전을 검증한다.
일반 시각 분류·텍스트 맥락 검토·원음 전체 검증 범위를 합쳐서 승인하지 않는다.

다음 유료 호출은 후보 모델·실제 전송 문장·호출 수·가격을 다시 확인받은 뒤 실행한다.
기존 텍스트·미디어 실측은 보존하고 새로운 대조문 결과는 별도 파일로 기록한다.
독립적인 한국어 확장 표본과 사람 라벨 검토 없이 운영 공급자나 제품 정책을 확정하지 않는다.
DB/Storage의 승인 snapshot·읽기 차단·알림/Realtime/위젯 공개 경계는 기존 설계의 후속 작업이며 이번 범위에 포함하지 않았다.
