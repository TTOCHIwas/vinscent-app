# 월간 회고 구현 명세와 변경 범위

작성일: 2026-10-11

이 문서는 확정한 제품 요구사항과 구현 경계를 기록한다. 기존 운영 반영과 기기 설치 이력은 11절에 기록한다. 마지막 기기 설치는 `2026101702` 빌드다. 이후 회고 공통 아이콘과 사진 더미의 실제 경계 기반 여백 수정은 소스에 반영했으며 아직 기기에 재설치하지 않았다. 이번 후속 변경의 운영·스토어 배포는 수행하지 않았다.

## 1. 목적과 제공 방식

- 지난달 두 사람이 남긴 카드와 질문·답변을 돌아보고 각자 마지막 한마디를 남긴다.
- AI 화면은 기존 AI 질문을 유지하고 헤더의 `월간 회고` 버튼으로 독립 회고 화면(`/monthly`)을 연다. AI 질문과 월간 회고를 전환하는 상위 메뉴는 두지 않는다. 캘린더도 같은 화면을 열며, 뒤로가면 진입했던 화면으로 돌아간다.
- 캘린더 헤더 오른쪽의 일정 추가 왼쪽에 월간 회고 버튼을 둔다. 표시 중인 달이 현재 제공 중인 지난달이고 실제 카드나 답변 기록이 있을 때만 노출한다. 로딩·실패·빈 달·만료·종료된 관계에서는 숨긴다. 돌아오면 기존 선택 날짜와 스크롤을 유지한다. 버튼 유무와 관계없이 연도·월은 화면 정중앙에 고정한다.
- AI·캘린더의 회고 진입 버튼은 같은 `MonthlyRetrospectiveAction`을 사용한다. `book-heart` 아이콘 24px, 터치 영역 44px, 접근성 이름·길게 누르는 안내는 `월간 회고`다. 헤더에 회고 텍스트 버튼은 두지 않는다.
- 매월 1일부터 말일까지 지난달 회고를 제공한다. 예: 10월에는 9월 회고를 제공한다.
- 제공 기간에는 반복해서 열고 답변할 수 있다. 다음 달이 되면 새 회고로 전환한다.
- 진행 중인 달의 회고, 과거 월 선택, 과거 회고 보관함은 제공하지 않는다.
- 기존 24개 질문 완료 여부는 월간 회고의 이용 조건이 아니다.
- 제목·요약은 제공 기간에만 임시 캐시한다. 종료 후 캐시를 삭제하고 만료된 결과는 반환하지 않는다.
- 공통 회고 질문과 각자의 답변은 제공 종료 후에도 저장해 AI 질문·추천의 근거로 활용한다.
- 사진과 기존 질문·답변 원문은 복제하지 않고 원래 기록을 참조한다.
- 커플 관계가 종료되면 월간 회고 접근도 종료한다. 기존 캘린더의 원래 기록 조회는 기존 보관 정책을 따른다.
- 지난달 질문에 늦은 답변이 추가되면 통계·장면 선정·우리의 답은 최신 기록으로 갱신한다. 이미 제공한 제목·요약·공통 회고 질문은 유지한다.

## 2. AI 동의와 콘텐츠 경계

- 두 사람 모두 기존 AI 이용 동의가 있어야 AI 제목·요약·회고 질문을 생성하거나 저장된 회고 답변을 AI에 전달한다.
- 동의가 없어도 통계·기록 선정·원문 조회와 기본 회고 질문에 대한 답변 저장은 제공한다.
- 월간 요약과 기록 기반 회고 질문의 근거는 해당 월에 배정된 질문 중 두 사람 모두 답한 질문·답변이다.
- 한쪽만 답한 원문은 공유 요약을 통해 공개하지 않는다.
- 사진 픽셀 분석을 요구하지 않는다. 기록에 없는 사건·감정·관계 평가를 생성하지 않는다.
- AI에 전달하는 참여자 식별은 기존 익명화 경계를 따른다.
- 동의 철회 이후 생성·결과 반영·후속 AI 활용을 중지한다. 기존 질문과 회고 답변 자체의 조회·저장은 동의와 분리한다.
- 기본 질문 또는 AI 질문을 처음 사용자에게 제공할 때 저장하고 고정한다. 이후 동의·답변 상태가 바뀌어도 교체하지 않는다.
- AI 응답 로그에 제목·요약 원문을 장기 보관하지 않는다. 기존 작업 성공 로그에 결과를 저장하는 흐름을 재사용할 때 임시 보관 정책을 반드시 확인한다.

## 3. 통계 정의

| 표시 | 집계 기준 |
| --- | --- |
| 기록한 날 | 카드 또는 질문 답변이 하나 이상 있는 날짜의 중복 없는 수. 사진·그림·글 카드 모두 포함하고 한쪽 기록만 있어도 포함 |
| 남긴 카드 | 두 사람의 성공한 카드 저장 횟수에서 사용자가 직접 삭제한 횟수를 뺀 누적 카운트. 사진 개수나 보관 카드 행 수가 아님 |
| 함께 답한 질문 | 해당 월에 배정된 같은 질문에 두 사람 모두 답한 질문 수 |

- 질문이 배정되기만 하고 카드·답변이 없는 날짜는 기록한 날에서 제외한다.
- 질문·답변의 월 귀속은 `daily_questions.assigned_date`로 한다. 답변 작성 시각으로 월을 옮기지 않는다.
- 카드의 날짜는 기존 `couple_date`를 따른다. 기간 판정과 월 경계는 서버의 커플 시간대·현재 날짜를 기준으로 한다.
- 사진 4장이 들어 있는 카드도 남긴 카드 통계에서는 1개다.
- 카드 카운트는 첫 완전한 집계 월부터 제공한다. 집계 시작 전 또는 일부 기간만 집계된 월은 `집계 불가`로 표시한다.
- 집계 불가는 0개와 구분한다. 카드 카운트가 불완전해도 나머지 통계와 회고는 실제 기록에 따라 제공한다.

### 3.1 카드 카운트 저장 규칙

| 동작 | 누적 카운트 |
| --- | --- |
| 새 카드 저장 성공 | +1 |
| 사용자가 오늘의 카드 직접 삭제 성공 | -1 |
| 날짜 전환 후 대표 카드 외 자동 정리 | 유지 |
| 저장·삭제 실패 또는 같은 요청 재처리 | 추가 변동 없음 |

- 저장·직접 삭제와 카운트 변경을 같은 데이터베이스 트랜잭션으로 처리한다.
- 예: 하루에 3개 저장 후 직접 1개 삭제하면 2개. 자동 정리 후 대표 카드가 1개만 남아도 집계는 2개다.
- 모든 카드 삭제 트리거에서 일괄 차감하면 자동 정리도 차감되므로 허용하지 않는다.
- 직접 삭제의 소유자·당일 검증을 통과하고 실제 삭제가 발생할 때만 차감한다. 기존 저장 파일 정리 트리거는 유지한다.
- 저장 요청 재처리를 식별할 수 있는 키가 필요하다. 현재 전달하는 `requested_artifact_revision`과 실제 DB 유일성·재시도 경계를 구현 단계에서 함께 검증한다.
- 카운트가 0보다 작아지지 않게 하고, 카운트 누락을 조용히 0으로 처리하지 않는다.
- 도입 이전 누적 작성 수는 보관 카드만으로 복원할 수 없다. 보관 카드 수를 과거 누적 카운트로 대체하지 않는다.
- 집계 시작 시각과 첫 완전한 대상 월을 보관한다. 서버 커플 시간대 기준으로 해당 월 전체의 저장·직접 삭제 경로가 집계되었는지 판정한다.
- 최초 도입 월의 중간부터 집계했다면 그달도 집계 불가다. 다음 월부터 전체 월 집계를 제공한다.

## 4. 화면 명세

### 4.1 공통

- 라이트 모드만 구현한다. 첨부 시안의 검은 배경·다크 색상은 사용하지 않는다.
- 기존 `AppColors`, `AppTextStyles`, 캐릭터·말풍선·질문·답변 표시·`AppAnswerInput`을 재사용한다.
- 회고의 대상 연도·월은 본문 위 독립 화면의 최상단 공통 헤더에 표시한다. AI 헤더나 전환 메뉴를 위에 중첩하지 않으며 과거 월 선택 UI는 두지 않는다.
- 회고 헤더는 기존 `AppPageHeader`·`AppBackButton`을 사용한다. 공통 56px 높이와 뒤로가기 좌표를 따르고, 캘린더와 같은 `pageTitle`(20px·600) 및 `2026년 09월` 표기를 사용한다. 제목은 버튼과 겹치지 않는 중앙 영역에 표시하고 우측 `월간 회고` 문구는 두지 않는다. 로딩·오류·월 전환 안내에도 동일 헤더를 유지한다.
- 월간 회고는 하나의 세로 스크롤 화면이다. 내용 순서는 `지난달 이야기 → 우리의 답 → 그날의 기억 → 마음 남기기`다. 원문을 자르거나 강제로 축소하지 않는다. 좌우 스와이프·페이지 메뉴·하단 인디케이터는 제거한다.
- 소개와 공동 답변 영역에는 별도의 섹션 이름·설명을 두지 않는다. `그날의 기억`과 `마음 남기기`에는 제목과 보조 설명을 유지한다. 제목은 18px·600, 설명은 14px 중립색이며 제목과 설명 간격은 8px, 안내와 본문 간격은 20px다. 섹션 사이 간격은 64px로 통일하고 기억 목록 내부 간격은 16px로 유지한다. 월 소개 제목·실제 질문·내 답변/상대방 답변 구분은 유지한다.
- 안내 문구: `그날의 기억` — `사진이 남아 있는 날 중 최대 세 날의 기록을 골랐어요.` / `마음 남기기` — `같은 질문에 각자의 답을 남기며 한 달을 마무리해요.` 사진 장면이 없는 경우 기억 설명은 `지난달 사진이 담긴 날의 기록을 돌아봐요.`로 바꾸고 기존 빈 상태 안내를 유지한다.
- 타이포는 기존 Pretendard를 유지하고 역할별로 구분한다. 월 소개 제목·주 날짜는 24px·600, 연도·월 헤더·질문·통계 숫자는 20px·600, 섹션 제목은 18px·600, 답변 본문은 16px·400, 공통 캐릭터 말풍선은 16px·500, 보조 정보는 14px·400이다. 시스템 글자 확대를 적용하고 긴 내용을 자르지 않는다. Apple의 [텍스트 스타일과 계층 안내](https://developer.apple.com/videos/play/wwdc2020/10175/)를 참고한 앱 내 역할별 크기이며, 네이티브 iOS 스타일 수치를 그대로 적용한 것은 아니다.
- 대상 월별 스크롤 위치와 작성 중 답변을 유지한다. 기록 상세를 보고 뒤로 돌아오면 같은 스크롤 위치로 복귀한다. 새 제공 월은 맨 위에서 시작하며 이전 월 초안이 있으면 먼저 확인한다.
- 공동 답변이 없으면 `우리의 답` 영역만 생략하고 기억 목록과 마음 남기기는 유지한다. 카드·답변 모두 없는 달에는 기록 없음 안내만 표시한다.
- 회고와 회고 하위 기록 화면의 하단 독은 AI를 선택 상태로 표시한다. 실제 진입했던 화면으로 돌아가는 경로 및 초안 보호와 독의 선택 표시는 분리한다.
- 캐릭터와 텍스트는 캘린더 날짜 상세와 같은 `AiCharacterSpeechRow`의 기본 96px 크기·12px 간격·정렬·텍스트 스타일을 사용한다. 최대 360px 안에서 사용 가능한 폭을 채우고 남은 가로 영역을 텍스트에 배정해 문장 길이·생성 표시 유무와 관계없이 캐릭터와 텍스트 시작점을 통일한다. 생성 표시는 텍스트 영역 오른쪽 아래에 두며 신고 기능을 유지한다.
- 고정 헤더와 하단 독을 제외한 영역을 스크롤한다. 마지막 내용에 독·시스템 인셋 여백을 확보하고 키보드가 올라와도 입력과 저장 버튼에 접근할 수 있게 한다. 당겨서 새로고침은 두지 않고 기존 자동 갱신·재시도는 유지한다.
- AI 생성 실패는 소개 영역, 답변 저장 실패·동시 수정 충돌은 입력·저장 버튼 근처에 표시한다. 실패 시 초안과 편집 버전을 보존한다.
- 기존 AI 질문, 학습 동의·진행, 질문 이력, 기억 확인 기능은 유지한다. 회고 로딩·실패가 기존 AI 화면을 막지 않는다.

### 4.2 지난달 이야기

대상 월은 고정 헤더에 표시한다. 첫 소개 영역에는 별도의 섹션 이름·보조 설명을 두지 않는다. 소개 제목 → 24px 여백 → 세 통계 → 32px 여백 → 공통 캐릭터 말풍선 요약을 한 묶음으로 배치하고, 초기 화면에서 하단 독과 12px 여백을 둔다. 정보 묶음의 실제 높이를 먼저 측정하고 남은 위쪽 영역에 카드 더미를 배치한다. 회전된 카드와 그림자를 포함한 전체 경계를 계산하고, 헤더 하단부터 더미 상단까지와 더미 하단부터 소개 제목까지의 여백을 같게 맞춘다. 두 여백은 최소 16px이며 본문 위 여백 12px도 계산에 포함한다. 더미 전체는 가로 중앙에 두고 사용 가능한 폭·높이에 맞춰 균일하게 축소한다. 카드 비율·상대적인 겹침·회전은 유지한다. 큰 글자·긴 내용에서는 카드의 최소 표시 공간을 확보하고 전체 내용을 세로로 스크롤할 수 있게 한다.

- AI 제목은 실제 답변 근거로 생성한다. AI를 사용할 수 없으면 `우리의 9월`처럼 대상 월 기반 기본 제목을 쓴다.
- 대상 월의 실제 보관 대표 카드 수에 따라 1~3개면 모두, 4~9개면 4장, 10~19개면 6장, 20개 이상이면 8장을 사진·그림·글 구분 없이 고른다. 누적 카드 카운트는 선정 개수 기준으로 사용하지 않는다. 두 작성자에게 균등하게 배분하고 각 작성자의 월초부터 월말까지 고르게 선택한다. 한쪽 카드가 부족하면 나머지 보관 카드로 보충한다. 날짜·작성자·ID 순서를 기준으로 결정해 같은 데이터는 같은 배치를 유지한다. 자동 정리된 과거 카드의 복원을 의미하지 않으며 누적 카드 통계와 표시 장수는 다를 수 있다.
- 실제 카드 미리보기를 바닥에 흩어 놓은 것처럼 회전·겹침·그림자로 표현한다. 회고의 줄과 집게는 제거하며 홈의 기존 연출은 유지한다. 카드 더미 자체에 새 기능을 추가하지 않고, 누른 카드 ID의 공통 상세보기를 바로 연다. 이미 사라진 카드라면 다른 카드로 대신 표시하지 않고 안내한다.
- 보관 카드가 없으면 카드 영역을 생략한다. 원래 카드 비율을 유지하고 작은 미리보기 해상도로 디코딩한다. URL은 공용 캐시에서 만료를 판단하고 화면 갱신 때 재검증한다.
- 요약은 2~3문장이다. 두 답변을 비교·평가하거나 근거 없는 내용을 덧붙이지 않는다.
- 공동 답변이 없거나 AI 동의가 없으면 생성 요약 대신 사실에 근거한 기록 현황 안내를 표시한다.
- 늦은 답변이 추가되어 통계·선정이 달라져도 이미 제공한 제목·요약은 교체하지 않는다. 임시 캐시 수명은 기존 제공 종료 시각으로 유지한다.

### 4.3 우리의 답

- 사진 여부와 무관하게 두 사람이 모두 답한 질문만 대상으로 한다.
- 공백·줄바꿈을 제외한 두 답변 글자 수 합계가 가장 큰 질문 1개를 고른다. 동점이면 배정 날짜가 빠른 질문을 고른다.
- 공통 `RecordDateLabel`을 캘린더 상세와 함께 사용한다. `9월 14일`은 24px·600으로, 날짜 옆에 `둘이 가장 길게 답한 질문`을 14px 중립색으로 표시한다. 좁은 폭·큰 글씨에서는 설명을 다음 줄로 옮긴다. 그 아래 연도·요일은 작은 보조 글씨로 표시하고, 이어서 질문 → 내 답변 → 상대방 답변을 배치한다. 캘린더의 기본 날짜 표시는 설명 없이 유지한다.
- 원문 전체를 표시하고 긴 내용은 전체 화면의 세로 스크롤로 확인한다. 선정용 문자열과 표시용 원문을 구분한다.
- 기존 `QuestionAnswerOverview`와 답변 표시 컴포넌트를 우선 재사용한다. 현재 표시 과정의 `trim()` 적용과 기존 저장 정규화를 구분하고, 회고에서 원문을 추가 가공하지 않는다.
- `우리의 답`은 기존 일일 답변 식별자를 사용하므로 기존 신고 경로를 유지한다. 신규 회고 답변은 일일 답변 ID로 가장하지 않고, 표시 컴포넌트의 신고 액션과 서버 대상 검증을 회고 식별자에 맞춰 연결한다.
- 캐릭터의 다시 읽기 안내는 고정 문구다. 이 고정 안내에 AI 생성 표시를 붙이지 않는다.
- 후보가 없으면 이 영역만 생략한다.

### 4.4 그날의 기억

선정 단위는 사진 한 장이 아닌 날짜별 장면이다.

1. 실제 보관된 카드에 `has_photo = true`인 날짜만 후보로 삼는다.
2. 월초 1~10일, 중순 11~20일, 월말 21일~말일에서 각각 하루를 선택한다.
3. 구간 내에서 질문 답변이 하나 이상 있는 날짜를 우선한다. 한쪽 답변만 있어도 포함한다.
4. 같은 우선순위에서는 두 답변의 공백·줄바꿈 제외 글자 수 합계가 큰 날짜를 고른다. 누락 답변의 길이는 0이다.
5. 동점이면 날짜가 빠른 날을 고른다.
6. 구간별 선정을 끝낸 후 빈자리는 아직 선택하지 않은 전체 후보에서 같은 기준으로 보충한다.
7. 후보가 3일 미만이면 있는 만큼만 표시하고, 최종 결과는 날짜순으로 정렬한다.

- 서버에서 선정한다. 조회자에게 숨겨진 답변을 길이 0으로 계산해 두 사람의 결과가 달라지면 안 된다.
- 숨겨진 답변 원문·개별 길이는 화면에 반환하지 않는다.
- 장면은 작은 카드 묶음을 왼쪽에, 날짜·그날의 질문·기록 보기 링크를 오른쪽에 가로 배치한다. 최대 세 장면을 세 행으로 표시한다.
- 장면의 카드도 줄·집게 없이 날짜별 1~2장을 작게 겹쳐 보여주며 긴 네컷 카드도 원래 비율을 유지한다.
- 두 작성자 모두 보관 사진 카드가 있으면 같은 장면에 함께 표시한다. 그림·글만 있는 카드는 사진 장면에 넣지 않는다.
- 답변 발췌·AI 인용문은 표시하지 않는다. 질문이 없는 날은 날짜와 카드만 표시한다.
- 카드를 누르면 해당 카드의 공통 상세보기를 연다. `그날의 기록 보기`는 기존 캘린더의 해당 날짜로 이동하며 뒤로 가면 회고로 복귀한다.
- 후보가 없으면 `지난달에는 사진이 담긴 카드가 없어요` 안내를 표시한다.

### 4.5 마음 남기기

표시 순서: 캐릭터의 공통 질문 → 내 답변 입력·저장 → 상대방 답변.

- 질문은 고마웠던 순간, 다시 하고 싶은 일, 다음 달 함께하고 싶은 일 등을 묻는다.
- 기록 근거 또는 AI 동의가 부족하면 사건을 가정하지 않는 기본 질문을 사용한다.
- 입력란 이름은 `내 답변`, 최초 저장 버튼은 `마음 남기기`다. 최대 500자이고 여러 줄을 허용한다.
- 저장 버튼은 입력란과 같은 전체 너비를 사용하며 글자 수와 저장 오류 안내 아래에 배치한다. 저장 중에도 같은 너비를 유지한다.
- 빈 답변·공백만 있는 답변은 저장하지 않는다. 글자 수 기준은 기존 답변 입력 기준과 DB 검증을 대조해 통일한다.
- 저장 후 내 답변과 `수정하기`를 표시한다. 제공 기간에는 두 사람의 완료 여부와 관계없이 본인 답변을 수정할 수 있다.
- 제공 종료 후 수정 불가다. 과거 답변의 사용자 조회 진입점은 제공하지 않되 데이터는 AI 활용을 위해 유지한다.
- 내 답변 저장 전에는 상대방 원문을 숨긴다. 저장 후에는 상대방 답변 또는 아직 답변하지 않았다는 안내를 표시한다.
- 스크롤·기록 상세 왕복 시 입력 유지. 회고를 닫을 때 미저장 내용이 있으면 확인한다.
- 일반 일일 질문과 별도로 저장한다. `daily_questions`를 생성하거나 일일 질문 완료 수를 증가시키지 않는다.

## 7. 저장·조회 계약 설계안

### 7.1 영구 데이터

- 일별 카드 카운트: 커플·작성자·기록 날짜별 카운트와 집계 완전성 시작 기준. 기존 보관 카드와 수명을 분리한다.
- 월별 공통 질문: 커플·대상 월별 유일한 질문, 기본/AI 출처, 생성 시각, 제공 종료 시각, 질문 버전.
- 회고 답변: 공통 질문·작성자별 유일한 답변 원문, 작성·수정 시각, 동시 수정 판정용 버전.
- 조회자·작성자의 커플 소속과 활성 관계, 기존 UGC 입력 정책을 검사한다. 상대 답변 공개 조건은 DB에서 적용한다.
- 기존 커플 삭제·계정 삭제·보관 종료 규칙과 정합성을 맞춘다. 회고 데이터만 관계 밖으로 남겨 다른 커플에 사용하지 않는다.

### 7.2 임시 데이터

- 커플·대상 월별 제목·요약 캐시와 상태, 만료 시각, 작업 식별자, 동의 버전.
- 동일한 생성 요청을 합쳐 중복 AI 호출과 서로 다른 결과 확정을 막는다.
- 캐시 만료 여부는 조회 시 검사하고, 만료 데이터 삭제도 운영 경로에 포함한다.
- 진행 중 생성 결과가 질문 고정·기간 종료·동의 철회를 덮어쓰지 않도록 결과 반영 시 다시 검증한다.
- 관계 종료 이후 진행 중 생성 결과를 반영하지 않는다. 캐시가 남아 있어도 종료된 관계의 회고 조회를 허용하지 않는다.
- 표지·장면·우리의 답 식별자는 원본 조회와 규칙 계산으로 얻는다. 영구 회고 스냅샷은 만들지 않는다.
- 원본 답변 변경으로 통계·선정 읽기를 무효화할 수 있으나, 이미 제공한 제목·요약 캐시는 재생성하지 않는다.

### 7.3 API 책임

| 구현 계약 | 책임 |
| --- | --- |
| `get_current_monthly_retrospective_availability` | 활성 커플의 대상 월·만료 시각·기록 존재 여부만 조회. 회고·요약 캐시·질문을 생성하거나 고정하지 않는 stable RPC. 버튼 노출에만 사용 |
| `get_current_monthly_retrospective` | 활성 관계와 서버 제공 월 검증, 최신 통계·선정 장면·공동 답변 원문·기존 캐시 상태·고정 질문·조회자 답변 상태 반환 |
| `generate-monthly-retrospective` Edge 함수 | 사용자 토큰 인증, 동의·기록 근거 확인 후 중복 없는 월간 AI 작업 요청 |
| `use_basic_monthly_retrospective_question` | 기본 질문 최초 확정. AI 결과가 뒤늦게 도착해도 고정된 질문 유지 |
| `submit_current_monthly_retrospective_answer` | 활성 제공 기간·질문·작성자 검증 후 최초 저장/수정, 상대 답변 공개 상태 반환 |
| `prepare_monthly_retrospective_generation` / `finish_monthly_retrospective_generation` | 서비스 역할 전용 생성 컨텍스트·결과 반영. 공동 답변 제공, 질문 고정·기간·동의 버전 검사, 임시 요약 캐시 기록 |
| 후속 AI 컨텍스트 조회 | 저장 질문·답변·대상 월을 권한과 동의에 맞춰 전달 |

- 함수명·인자·반환 타입은 migration과 계약 테스트에 고정한다.
- 캘린더 버튼 판정은 회고 전체 조회와 분리한다. 동일 커플·대상 월·기록 존재·실제 UTC 만료 시각을 검증하며, 카드·답변 변경과 최대 30초 주기로 읽기를 갱신한다. 제공 월 판정에는 커플 날짜를 사용한다.
- 카드 통계 계약에는 값과 집계 완전성을 별도로 포함한다. 집계 불가 값은 null이며, 완전한 집계에서 카드가 없을 때만 0이다.
- 조회·쓰기·생성 요청뿐 아니라 작업 컨텍스트 조회와 결과 반영 시에도 활성 커플 관계를 검사한다.
- 월 조회를 위해 하루마다 상세 RPC를 반복 호출하지 않는다. 월별 집계·순위를 서버에서 묶어 조회한다.
- 소개 영역에 표시할 보관 카드 전체와 선정 장면의 미리보기 경로를 배치 단위로 서명하고 공용 캐시를 공유한다. 서명 URL 자체는 영구 저장하지 않는다.

### 7.4 AI 질문·추천으로 연결

- 저장된 회고를 단순 보관으로 끝내지 않고 후속 질문·추천 컨텍스트 로더에 연결한다.
- 질문 원문·답변 원문·대상 월·작성자·최신 버전을 함께 전달한다.
- 특정 월의 바람을 영구 취향이나 관계 진단으로 승격하지 않는다. 기존 기억 확인 절차를 우회하지 않는다.
- 수정 이후 최신 답변을 사용하고, 동의가 없으면 모델 입력에서 제외한다.
- 상대 답변이 숨겨진 상태에서 질문·추천을 통해 원문 내용이 노출되지 않도록 기존 공개 권한과 대조한다.
- 기존 선제 추천은 큐레이션 선택 경계도 있으므로, 회고 활용은 컨텍스트와 선정 정책까지 연결해 실제 영향을 검증한다.

## 9. 구현 순서와 완료 조건

1. 확정한 카드 카운트 적용 시작 정책에 따라 완전한 집계 월·집계 불가 표시 및 저장·직접 삭제·자동 정리의 계약 테스트를 작성한다.
2. 일별 카운트와 중복 방지 경계를 구현한다. 과거 불완전 값을 정확한 전체 카운트로 표시하지 않는다.
3. 월 집계·선정 및 회고 질문·답변 API를 구현한다. 서버 권한·기간·질문 고정을 검증한다.
4. AI 생성 계약과 한 달 캐시 수명을 구현한다. 동의 없는 기본 질문도 동일한 고정 경계를 사용한다.
5. 모바일 AI 헤더의 진입 버튼과 독립 회고 화면을 연결한다. 소개 영역부터 기존 라이트 UI와 대조한다.
6. 우리의 답 → 그날의 기억 → 마음 남기기 순서로 구성하고 초안·복귀·저장 실패를 검증한다.
7. 저장 회고의 후속 AI 질문·추천 활용을 연결한다. 단순 저장 완료를 기능 완료로 취급하지 않는다.

필수 검증:

- 구간 선정, 답변 유무 우선, 공백·줄바꿈 제외, 동점, 빈 구간 보충, 0~2개 후보, 날짜순 표시.
- 한쪽 미답변 사용자 두 명의 장면 선정 동일성과 숨겨진 원문 비노출.
- 보관 카드에 사진이 없는 날짜 제외, 두 사람 사진 동시 표시, 캘린더 이동·복귀.
- 카드 저장·직접 삭제·자동 정리·요청 중복·동시 실행에서 카운트 정합성.
- 집계 시작 전·월 중간 도입·첫 완전한 월·완전한 0개와 집계 불가의 구분.
- 최초 기본/AI 질문의 동시 제공, 동의 변경, 늦은 생성 결과에도 질문 고정.
- 답변 최초 저장·500자 검증·수정·상대 공개·월 종료·다른 커플 접근 거절.
- 캐시 동일 결과 제공, 월 경계 만료, 만료 삭제, 생성 중 동의 철회.
- 관계 종료 후 조회·쓰기·캐시 접근·작업 컨텍스트 조회·늦은 생성 결과 반영 거절. 기존 캘린더 보관 조회 유지.
- 지난달 질문에 늦은 답변 추가 시 통계·장면·우리의 답 갱신, 기존 제목·요약·공통 질문 유지.
- 24개 질문 미완료 상태에서도 회고 제공, 기존 AI 기능과 일반 질문 상태 불변.
- 후속 AI 컨텍스트의 질문·월·최신 답변 반영, 동의 철회 제외, 일시적 바람의 영구 취향 오인 방지.

위 동작 검증과 프로젝트의 `code-architecture-and-verification.md` 기준을 적용했다. 실제 Supabase 전체 migration·운영 배포 결과와 기기 검증 잔여 항목은 11절에 기록한다.

## 10. 추가 확정 사항

아래 항목은 사용자 승인으로 확정했고 통계·접근 권한·캐시·검증 기준에 반영했다.

1. 카운트 도입 이전 기간: 불완전한 기간은 집계 불가로 표시하고 첫 완전한 월부터 카드 수를 제공한다. 과거 전체 작성 수를 추정하거나 보관 카드 수로 대체하지 않는다.
2. 관계 종료 후 회고 접근: 월간 회고 접근을 종료한다. 원래 기록은 기존 캘린더 보관 정책을 적용한다.
3. 지난달 질문에 이번 달 늦게 답하는 경우: 통계·선정 결과는 갱신하되 이미 제공한 제목·요약·공통 회고 질문은 유지한다.

현재까지 논의한 제품 결정은 모두 반영했다. 함수명·반환 타입·동시성 제어 등 구현 상세는 기존 코드와 위 계약에 맞춰 정하되, 확정한 제품 동작을 변경하지 않는다.

## 11. 구현 결과와 운영 적용

### 구현 결과

- AI 헤더와 캘린더에서 같은 독립 월간 회고 화면을 연다. 회고는 기존 24개 질문 완료 조건과 독립적이다.
- 지난달 이야기, 그날의 기억, 우리의 답, 마음 남기기를 기존 라이트 테마와 질문 표시·입력 컴포넌트로 구성했다. 공동 답변이 없으면 우리의 답 메뉴를 생략한다.
- 카드 통계는 작성 receipt와 일별 카운트를 사용한다. 동일 요청 재시도는 한 번만 집계하고 직접 삭제만 차감한다. 자동 정리는 카운트를 보존한다.
- 카드 집계 시작일은 첫 migration 적용 시각이다. 해당 커플 시간대의 월 전체가 집계 시작일 이후인 첫 대상 월부터 숫자를 표시하고, 그 이전 월은 집계 불가로 표시한다.
- 장면 선정은 서버에서 월 구간·답변 존재·공백 제외 길이·날짜 순위를 계산한다. 보관된 작성자별 대표 카드만 표시한다.
- 제목·요약은 제공 기간에 캐시하며 만료 시 조회에서 제외한다. 조회 경로와 매시간 정리 작업에서 만료 캐시를 삭제한다. 공통 질문·각자의 답변은 관계에 귀속해 저장한다.
- 회고 질문과 답변은 후속 AI 질문 및 큐레이션 추천에 연결했다. 양쪽 동의와 공개 조건을 확인하고 최근 3개월의 월 맥락을 전달한다.
- AI 생성물과 상대 답변의 신고 경로를 연결했다. 서버에서 실제 신고 대상과 원문 snapshot을 검증한다.
- 화면은 30초마다 최신 상태를 조회한다. 편집 중에는 초안과 편집 시작 버전을 보존한다. 다른 기기의 수정과 충돌하면 최신 답변과 초안을 제시하고 사용자가 저장할 내용을 선택한다.
- 회고의 세로 스크롤과 원래 기록 왕복은 초안을 유지한다. 회고를 벗어나는 하단 탭 이동·시스템 뒤로가기는 저장하지 않은 답변의 종료 확인을 거친다. 그날의 기록을 확인한 뒤 뒤로 가면 회고로 돌아온다.
- 기존 일일 질문, 캘린더 원래 기록, AI 학습·기억·직접 질문과 카드 저장 RPC 반환 계약을 유지했다.
